<interfaces>
Use the established verifier-owned `.muxy-hermes-qualification/current/` workspace directory, but add separate fixed recovery challenge and receipt filenames so Phase 1 connection receipts remain unchanged. A recovery challenge contains exact version, nonce, expiry, expected canonical condition, expected lifecycle (`same_panel` or `recreated_panel`), and expected safe signature codes. The panel receipt contains only version, challenge digest, panel-instance digest, lifecycle, bounded observer-attempt count, normalized status class, signature codes, and outcome digests. The Node projector accepts exact correlated panel/fixture/cleanup objects, computes one receipt-bundle digest, updates only the challenged canonical row, validates the complete document, and atomically replaces the requested output path. It never imports Node file I/O into the browser bundle.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| native panel snapshot → verifier receipt | Content-bearing run state crosses into a fixed allowlisted digest/enumeration contract. |
| verifier receipt bundle → public evidence | Multiple ephemeral receipts must correlate before one canonical row can change. |
| public evidence → panel DOM | Only sanitized controlled labels may become user-visible text. |
| concurrent projector → evidence file | Writers must not cross-correlate bundles or truncate the canonical document. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-03-01 | Information disclosure | recovery receipt/evidence | high | mitigate | Exact schemas, controlled enums, digest-only provenance, sentinel tests, and no raw run/session/network/path fields. |
| T-03-03-02 | Spoofing | native observation claim | high | mitigate | One-use expiring verifier challenge plus correlated panel/fixture/cleanup digests and lifecycle predicates. |
| T-03-03-03 | Tampering | evidence projection | high | mitigate | Exclusive bounded lock, complete-document validation, restrictive temp file, and atomic rename. |
| T-03-03-04 | Repudiation | cleanup claim | medium | mitigate | Require a correlated cleanup receipt digest before a real row can become complete. |
| T-03-03-05 | Elevation of privilege | panel receipt writer | high | mitigate | Reuse existing `muxy.files` permission and fixed project-relative paths; add no background, storage, HTTP, or exec calls. |
| T-03-SC | Tampering | package supply chain | high | mitigate | Add no package or install task and preserve the committed lockfile. |
</threat_model>
