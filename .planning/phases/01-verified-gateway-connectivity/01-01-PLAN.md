## Trust Boundaries

| Boundary | Description |
|---|---|
| user → panel memory | Runtime URL and full-authority bearer enter an ephemeral WKWebView state boundary. |
| panel → Hermes | Cross-origin browser requests carry bearer auth and receive capability/SSE data. |
| source → npm/build/dist | Approved starter dependencies and manifest assets become executable shipped output. |
| raw stream → rendered/committed data | Potentially sensitive Hermes payloads must be reduced before display or later evidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-01 | Information disclosure | URL/token form, GatewayClient, DOM, dist | high | mitigate | Hold bearer in a private in-memory closure, send only an Authorization header, abort/release on teardown, and test that render/copy/build outputs receive no secret. |
| T-01-02 | Elevation of privilege | Hermes CORS boundary | high | mitigate | Treat only an exact observed non-null origin as eligible; wildcard/reflection/absence never becomes a successful stage. |
| T-01-03 | Tampering / Information disclosure | non-loopback transport | high | mitigate | Reject non-loopback plaintext locally and rely on normal WebKit certificate validation with no bypass path. |
| T-01-04 | Elevation of privilege | manifest and client transport | high | mitigate | Use only direct panel fetch; structural manifest validation forbids helper/background/process/Docker/SSH/terminal/Git/filesystem authority and topology detection. |
| T-01-05 | Information disclosure | SSE parsing and result rendering | high | mitigate | Return allowlisted frame metadata only; never retain raw payloads or headers for later evidence. |
| T-01-SC | Tampering | npm install/build inputs | high | mitigate | Blocking human legitimacy checkpoint verifies the current Muxy starter's official Vite/TypeScript packages and lockfile before installation. |
</threat_model>
