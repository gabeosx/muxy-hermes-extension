<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| raw harness observation → sanitizer | Endpoint, header, token, workspace, and payload data may be present only ephemerally. |
| sanitizer → repository evidence | Only schema-validated allowlisted data may become durable. |
| concurrent runner → shared index | Multiple fixture lanes may append without corrupting or losing history. |
| evidence → user support belief | Classification can create an unsafe support claim if simulation or missing checks pass. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-01 | Information disclosure | validation input/errors | high | mitigate | Never emit raw input/errors; sanitize in memory and use safe reason codes before writes. |
| T-01-02 | Elevation of privilege | origin verdict field | high | mitigate | Schema accepts only exact-origin pass evidence from controlled observations; wildcard/null/reflection cannot satisfy required stages. |
| T-01-03 | Tampering / Information disclosure | trust class and transport evidence | high | mitigate | Classifier requires trusted HTTPS for non-loopback real paths and records no certificate-bypass concept. |
| T-01-04 | Elevation of privilege | deployment verdict model | high | mitigate | Classifier uses evidence flags, not infrastructure probing; harness authority never becomes an extension capability. |
| T-01-05 | Information disclosure | JSON/Markdown/index/SSE evidence | high | mitigate | Allowlist projection, schema validation, canonical sanitized hashes, synthetic secret scans, and atomic writes prevent raw payload retention. |
</threat_model>
