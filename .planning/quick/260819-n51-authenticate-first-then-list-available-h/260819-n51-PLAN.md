# Quick task 260819-n51

Replace the pre-authentication free-text board field with an authenticated board picker driven by Hermes's real board catalog.

The installed Hermes build under test exposes `GET /api/plugins/kanban/boards` after Dashboard authentication and returns `{ boards: [...], current: <slug> }`. Each server entry contains `slug`, `name`, `description`, `is_current`, `total`, and additional internal metadata such as `db_path`, `default_workdir`, counts, project identifiers, and styling fields. The extension must retain only the fields required for selection and must never render, store, or log the raw payload or internal paths.

## Task 1: Add the authenticated Hermes board catalog contract

**Files:** `src/kanban-client.js`, `scripts/run-kanban-fixture.mjs`, `test/kanban-client.test.js`, `test/kanban-fixture.test.js`

**Action:** Extend the existing session-backed Kanban client with a pre-selection catalog path. A client with a verified `DashboardAuthSession` may call `GET {baseUrl}/api/plugins/kanban/boards` without a `board` query parameter, normalize the `{ boards, current }` response, and then accept a selected slug before any board/task route is used. Allowlist and freeze only a bounded `slug`, display `name`, optional `description`, non-negative `total`, and current-selection flag; normalize every slug through the existing Hermes slug rule, derive the current choice only when it names an allowlisted entry, de-duplicate by slug, and drop `db_path`, `default_workdir`, project metadata, colors/icons, unknown fields, and the raw response. Keep the existing 401/403, 404, malformed-contract, and generic failure classifications, with no credentials/cookies in URLs or bodies. Mirror the pinned endpoint and response in the deterministic fixture. Add tests for the exact endpoint, response parsing, empty/single/multiple and duplicate catalogs, unsafe/malformed entries, deterministic preferred/current/first selection, response-field redaction, and authorization failures.

**Verify:** `node --test test/kanban-client.test.js test/kanban-fixture.test.js`

**Done:** The client can discover the pinned Hermes catalog only through an already-verified session, returns a small safe board-choice model for empty/single/multiple responses, and cannot call a board-scoped route until a catalog slug is selected.

## Task 2: Implement the authenticate-then-choose-board UI flow

**Files:** `src/board/app.js`, `src/styles/board.css`, `src/session-broker.js`, `test/board-ui-contract.test.js`, `test/session-broker.test.js`, `test/board-selection.test.js`

**Action:** Refactor the board tab into four explicit user-facing stages: (1) enter only the Dashboard address and check its sign-in options, (2) let the user enter credentials for an advertised password provider, (3) after successful login and `/api/auth/me` verification, load the catalog and show a labeled native `<select>` plus an `Open board` button, and (4) load/render the selected board. Remove the pre-auth free-text slug input and change the sign-in action copy so it does not claim the board opens immediately. Use friendly copy such as `Choose a board`, `No boards are available`, and `Open board`; do not expose protocol, storage, filesystem, or relay terminology. For a single result, select it in the still-visible dropdown; for multiple results, prefer a still-available saved slug, then the server's current slug, then the first catalog entry; for an empty result, keep the user signed in, disable opening, and show the empty state. Persist only the verified auth session plus selected slug through the existing `SessionBrokerClient`, clear username/password immediately after each attempt, and keep logout/session-expiry behavior unchanged. On restore, verify the stored session, fetch a fresh catalog, discard a saved slug that is no longer returned, and stop at the picker rather than opening a board before the user confirms. Add a narrow dependency-injection seam or extracted pure selection helper so Node tests behavior rather than relying only on source regexes. Test initial absence of a board field, login leading to catalog selection without loading a board, empty/single/multiple selection, explicit open using the chosen slug, restored-session preferred/fallback selection, logout/expiry clearing, and extension-storage round trips. Keep all styling on Muxy theme tokens and the established spacing/control scale, with visible focus and reduced-motion behavior.

**Verify:** `node --test test/board-selection.test.js test/board-ui-contract.test.js test/session-broker.test.js && npm test && npm run build`

**Done:** A user enters a Dashboard address, signs in themselves, chooses from the authenticated Hermes board dropdown, and explicitly opens that board; restored valid sessions return to the same picker without re-entering credentials.

## Threat model

- Usernames and passwords are accepted only in the visible sign-in form, cleared after every attempt, and never persisted, logged, included in tests, or sent anywhere except the selected Hermes Dashboard login endpoint.
- Board discovery occurs only after `/api/auth/me` verifies the Dashboard session; a 401/403 invalidates the local board surface and follows the existing session-expiry cleanup path.
- The catalog response is untrusted. Validate and bound every retained field, render option labels as DOM text, de-duplicate slugs, and never retain internal filesystem paths or raw response objects.
- Dashboard cookies, verified identity, Dashboard base URL, and the selected slug may persist only through `muxy.storage` via `SessionBrokerClient`; the board catalog itself is refreshed and remains in panel memory.
- A catalog slug is the only accepted board target. Do not reintroduce a free-text fallback, infer a board from a Muxy project/worktree path, or use Hermes's process-global board switch endpoint.
- Keep the existing exact deployment-neutral Dashboard URL contract and authenticated request relay; do not add a topology-specific transport, background owner, or new permission.
