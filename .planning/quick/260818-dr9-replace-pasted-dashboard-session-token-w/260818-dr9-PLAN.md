# Quick task 260818-dr9

Replace the Kanban board's pasted-token setup with the real Hermes Dashboard password-session contract while preserving the separation from the Gateway API-key connection.

## Task 1: Add a secret-safe Dashboard session relay

**Files:** `src/curl-relay.js`, `test/curl-relay.test.js`

**Action:** Add a bounded JSON request method for Dashboard auth that places credentials/cookies/body only in curl config stdin, captures response headers/body into a random fixed runtime subdirectory, parses only status/JSON/Set-Cookie, and scrubs then deletes response artifacts in `finally`. Reject control-character/config injection, oversized or malformed output, redirects outside the expected logout response, and calls without the existing Muxy files surface. Do not change the established Gateway bearer path.

**Verify:** `node --test test/curl-relay.test.js`

**Done:** Tests prove usernames, passwords, cookies, and sentinels never enter argv or durable output and that success/failure both scrub artifacts.

## Task 2: Implement provider-aware Dashboard authentication

**Files:** `src/dashboard-auth.js`, `src/kanban-client.js`, `scripts/run-kanban-fixture.mjs`, `test/dashboard-auth.test.js`, `test/kanban-client.test.js`, `test/kanban-fixture.test.js`

**Action:** Discover `/api/status` and `/api/auth/providers`; allow password login only for advertised password providers; POST `/auth/password-login`; merge only Hermes session cookies in memory; verify `/api/auth/me`; expose a frozen safe identity/provider/expiry state; rotate cookies returned by later responses; classify 401 as logged out/session expired; and POST `/auth/logout` before clearing. Convert KanbanClient from a caller-provided bearer to a verified session request callback. Update the disposable fixture to model provider discovery, rate-safe credential rejection, HttpOnly session cookies, `/api/auth/me`, expiry, logout, and board authorization without printing credentials or tokens.

**Verify:** `node --test test/dashboard-auth.test.js test/kanban-client.test.js test/kanban-fixture.test.js`

**Done:** A real fixture login validates identity, creates/moves cards while logged in, expires/logs out truthfully, and cannot use a pasted bearer token.

## Task 3: Replace the board token form with session UI

**Files:** `src/board/app.js`, `src/styles/board.css`, `package.json`, `test/board-ui-contract.test.js`, `test/phase-boundary.test.js`

**Done:** No source or built board contains a dashboard token input/copy, and the UI plus tests reflect authoritative session state end to end.

## Threat model

- Passwords and session cookies are high-value secrets: never place them in argv, URLs, logs, storage, evidence, test snapshots, or persistent files.
- Provider discovery is authoritative: do not show a password form for OAuth-only or unknown providers.
- Session identity comes only from `/api/auth/me`; never infer login from a successful board response or local form submission.
- On 401/403, clear board state and all credentials before rendering logged out/expired.
- Logout is best-effort server revocation plus unconditional local secret erasure.
- The extension must not implement a fake OAuth flow, scrape Dashboard HTML, or treat the Gateway `API_SERVER_KEY` as a user session.
