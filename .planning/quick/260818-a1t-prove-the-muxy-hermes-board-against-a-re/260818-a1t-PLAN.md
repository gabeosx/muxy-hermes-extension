# Goal

Prove the Muxy Hermes project board against an isolated, real Hermes Agent dashboard and Kanban database, then remove the disposable runtime without touching the user's Hermes state.

# Tasks

1. Start the pinned real Hermes executable with a fresh task-owned `HOME`/`HERMES_HOME`, enable and initialize its bundled Kanban dashboard plugin, seed a dedicated board through the real Hermes CLI, and bind the dashboard only to an ephemeral loopback port.
2. Connect the built Muxy board tab to the real dashboard with Computer Use, load the seeded board, create a card, and move it to another status.
3. Verify the UI mutation through the real Hermes CLI/database surface, capture safe version/API facts, stop all owned processes, prove the loopback port is closed, and remove only the task-owned runtime root.

# Acceptance

- The process reports Hermes Agent v0.20.2 (2026.8.16) and uses the bundled real Kanban plugin/API rather than the Node analogue.
- Every Hermes data/config path is under one newly created `/private/tmp/hermes-kanban-real-*` root with mode `0700`.
- The dashboard binds only to `127.0.0.1` on a dynamically allocated port.
- Muxy visibly loads a real seeded board and completes one create-and-move workflow.
- The Hermes CLI observes the resulting card/status from the same SQLite-backed board.
- The dashboard process is stopped, the port is closed, and the exact owned runtime root is removed.
