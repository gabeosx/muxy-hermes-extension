# Technology Stack

**Project:** Hermes Agent Extension for Muxy
**Researched:** 2026-08-16
**Overall confidence:** MEDIUM — the supported host and Gateway APIs are current and primary-source verified; the actual origin emitted by a Muxy panel's `WKWebView` remains an intentionally unproven v1 acceptance test.

[MDN Streams](https://developer.mozilla.org/en-US/docs/Web/API/Streams_API/Using_readable_streams) **HIGH** |

| Technology | Version | Purpose | Why |
|------------|---------|---------|-----|
| None in the extension | n/a | v1 state | The Gateway already owns runs, sessions, and short-lived event replay. Keep connection token and live run state in the open panel's memory. Adding SQLite, a local daemon, or profile persistence would obscure the transport verdict. **HIGH** |

### Infrastructure

| Technology | Version | Purpose | Why |
|------------|---------|---------|-----|
| Existing user-operated Hermes Gateway | Exact version/commit captured per fixture | The sole agent backend | Model it as an HTTPS or HTTP-loopback service address plus bearer token. Do not install, start, inspect, or infer whether it is host-native, Docker, SSH-tunneled, or remote. Hermes defaults to `127.0.0.1:8642`, requires `API_SERVER_KEY`, and defaults browser CORS to disabled. [MDN Fetch/CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS), [MDN response streams](https://developer.mozilla.org/en-US/docs/Web/API/Response/body) **HIGH** |

### Supporting Libraries

| Library | Version | Purpose | When to Use |
|---------|---------|---------|-------------|
| `AbortController`, `TextDecoderStream`, `ReadableStream` | Web platform APIs | Cancel and decode fetch-backed SSE | Use directly. A readable `Response.body` lets the panel process bytes as they arrive; abort it when the user stops observing a run or the panel unloads. [MDN Fetch streaming](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch) **HIGH** |
| Tiny in-repo SSE frame parser | Project code, fixture-tested | Turn decoded event-stream lines into typed Hermes events | Prefer this to a dependency for v1: Hermes event framing is a contract to capture and test, and the parser needs only the standard `event:`, `data:`, `id:`, blank-line framing. Do not use `EventSource`: its constructor exposes only URL and `withCredentials`, not arbitrary request headers, so it cannot send the required bearer `Authorization` header. [MDN EventSource constructor](https://developer.mozilla.org/en-US/docs/Web/API/EventSource/EventSource) **HIGH** |
| `muxy.storage` | Current Muxy API | Post-v1 non-secret preferences only | Use only after v1 for labels, URLs, mappings, and UI preferences. It is persistent JSON storage, not a keychain or credential vault. Keep bearer material out of it. [Muxy Storage](https://muxy.app/docs/extensions/storage) **MEDIUM** |

## Transport Decision

**Recommendation: use direct authenticated `fetch()` from the open panel's `WKWebView` as the one v1 client transport, conditional on a recorded exact-origin CORS proof.** It is deployment-neutral because it addresses one Gateway URL; Docker, SSH, and remote workspaces are deployment details behind that address.

The transport is deliberately a proof gate. The panel must make a preflighted request with `Authorization`, record the request origin at the Gateway, verify response CORS headers and incremental event delivery, and retain a captured fixture. `Authorization` makes a cross-origin browser request preflighted; it cannot be bypassed client-side. [MDN CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS) **HIGH**

### Transport comparison

| Candidate | Local / private Gateway | Remote HTTPS Gateway | Live authenticated SSE | CORS / token behavior | Decision |
|-----------|-------------------------|----------------------|------------------------|-----------------------|----------|
| Panel `fetch()` with `Authorization: Bearer` and `response.body` reader | **Candidate; must prove.** Works only if the panel's emitted origin can be explicitly allowed. | **Candidate; preferred** with a valid certificate and exact CORS allowlist. | Yes, using a streamed fetch reader and a fixture-tested SSE parser. | Browser CORS applies; bearer header triggers preflight. Do not use cookies or `credentials: include`. | **Use for all v1 traffic if the origin proof passes.** |
| `muxy.http.fetch` native HTTP | No: Muxy rejects loopback, private ranges, `.local`, and aliases resolving there before consent. | Yes for request/response calls after per-host consent. | No suitable API: it resolves to `{ status, headers, body, truncated }`, with body text capped/truncated at 10 MB; no incremental response reader is exposed. | Native request is not CORS-bound and can carry headers, but this does not solve streamed local runs. | **Do not use as the Gateway client.** A capabilities-only side path adds divergent auth/error behavior and proves nothing about the SSE route. [Muxy HTTP](https://muxy.app/docs/extensions/http) **HIGH** |
| Muxy `background.js` + native HTTP | No native HTTP API exists in background scripts. | No native HTTP API exists in background scripts. | No supported streaming ownership path. | The documented escape hatch is `muxy.exec(['curl', …])`, which requires subprocess permission and gives the extension a deployment-specific host-side helper. | **Do not use in v1.** Background scripts cannot rescue the local SSE constraint and would broaden token/command authority. [Muxy Manifest](https://muxy.app/docs/extensions/manifest), [Muxy HTTP](https://muxy.app/docs/extensions/http) **HIGH** |
| `curl`/Node/Python helper or bundled sidecar | Technically possible only with new local-process authority. | Technically possible but duplicates TLS, reconnect, and secret handling. | Could stream, but Muxy exposes no supported native helper-stream channel to an open panel. | Requires command consent, secure IPC, process lifecycle, and a second token boundary. | **Do not build in v1.** It changes the project from an extension proof into a local-service product. **MEDIUM** |
| Small upstream Muxy native streaming bridge | Potential fallback if direct panel fetch cannot be safely allowed. | Could be designed for either destination class. | Yes only after Muxy exposes a chunked/streaming response contract. | Bridge must own host consent, SSRF policy, TLS validation, and token redaction. | **Post-v1 / negative-result contract only.** Specify this only after reproducibly demonstrating that the panel's origin is not safely allowlistable. **MEDIUM** |

## Required Request and Security Contract

1. Normalize and validate an operator-entered `http`/`https` base URL; reject URL userinfo, query/fragment, non-HTTP schemes, and implicit credential sources. Never auto-detect Docker, SSH, or a workspace path.
2. Prompt for the Gateway bearer token at panel creation and hold it only in the panel closure/state store. Send it only in the `Authorization` header to the selected origin. Clear it on panel teardown, extension disablement, URL change, and auth failure; never log, serialize, use in query strings, or put it in `muxy.storage`, `localStorage`, manifests, or fixtures.
3. Call authenticated `/v1/capabilities` first; treat it as feature negotiation. Start a run only after its relevant advertised features are present. Treat `401`, `403`, `429`, `5xx`, certificate failure, preflight failure, and malformed SSE as distinct errors.
4. Use `POST /v1/runs`, then one `GET /v1/runs/{id}/events` streamed fetch. Reconnect only while the run remains nonterminal; reconcile every reconnect/panel re-entry with `GET /v1/runs/{id}`. Hermes documents five-minute unconsumed event retention and terminal-status retention for this purpose. [Hermes Runs API](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/api-server.md) **HIGH**
5. For `http://127.0.0.1` only, allow plaintext in the v1 development proof because the connection is loopback/tunnel endpoint; require `https:` for every non-loopback destination. Do not add certificate-ignore, mixed-content bypass, self-signed-cert trust bypass, or token-in-URL modes.
6. Hermes grants access to terminal-capable tools. Never auto-approve; show the Gateway's approval choices only if capabilities advertise them. Do not send a run `cwd` or infer host/container paths in v1.

## V1 Proof Requirements vs. Post-V1 Product Requirements

| V1 must prove | Explicitly defer |
|---------------|------------------|
| A publish-valid Muxy panel built from the current scaffold, with `package.json` copied to `dist/`. | Marketplace delivery, backward compatibility across unpinned Muxy releases, or a framework migration. |
| One runtime-entered URL/token works with exact observed CORS origin, bearer auth, capabilities, streamed token/tool/approval/terminal events, and advertised stop/steer/approval controls. | Multiple profiles, stored configuration, keychain integration, pairing, or token refresh. |
| Reproducible results for host-native, Docker, SSH local-forward, and direct HTTPS fixtures, plus remote-Muxy-workspace lifecycle/namespace behavior; each fixture records Muxy version, Hermes version/commit, origin, capabilities, preflight, SSE frames, reconnect, and error outcome. | A promise that untested deployment variants work, or any topology-specific client implementation. |
| Close/reopen behavior: token re-entry, status reconciliation, and documented replay window while the panel remains the owner. | Durable background run ownership, closed-panel approvals, notifications, or background SSE. |
| A negative direct-transport result ends with a minimal Muxy streaming-bridge contract. | Implementing a sidecar, `curl` helper, Node service, Muxy core patch, Hermes plugin, or provider registration during v1. |

## Alternatives Considered

| Category | Recommended | Alternative | Why Not |
|----------|-------------|-------------|---------|
| Network path | Direct panel `fetch()` | `muxy.http.fetch` | Native HTTP is excellent for public, buffered APIs but its SSRF guard excludes the local/tunneled deployments and it provides only a completed text body. |
| SSE API | Fetch stream + in-repo parser | `EventSource` | `EventSource` exposes `withCredentials` but not a headers option, so it cannot transmit Hermes's bearer header. |
| Streaming owner | Open panel | `background.js` | Background has no `muxy.http.fetch` and must use an authorized subprocess; it is not a supported native SSE owner. |
| Runtime helper | No helper in v1 | `curl`, Node, Python, Docker companion | Adds subprocess consent, OS-specific lifecycle/IPC, duplicate TLS/auth parsing, and a persistent secret boundary before proving the simpler architecture. |
| Deployment detection | One Gateway URL contract | Detect Docker/SSH/remote workspace | URL topology does not establish tool filesystem semantics and leads to unsafe host assumptions. |
| Credentials | In-memory per panel | `muxy.storage`, manifest settings, browser storage | Persistent extension storage is not a secret store; raw bearer tokens grant full tool access. |
| CORS | Exact observed extension origin | `*`, `null`, origin reflection | The browser Authorization flow needs server-approved CORS. A wildcard/null/reflection policy turns the Gateway into an ambient authority. |

## Installation

```bash
# Create the extension with Muxy's current vanilla starter, then preserve its lockfile.
# In Muxy: Extensions → Create

npm install
npm run build
# The build must copy package.json into dist/ before Reload / publish validation.
```

Do not add a runtime HTTP, SSE, shell, Docker, SSH, database, or secret-storage package for v1. Add a dependency only when a captured fixture demonstrates a browser API gap that cannot be solved in the panel.
