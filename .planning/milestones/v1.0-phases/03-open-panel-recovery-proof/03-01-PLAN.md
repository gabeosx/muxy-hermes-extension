<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| panel/controller → consented curl relay | Bearer-authenticated requests cross only the existing stdin/journal boundary. |
| interrupted observer → replacement observer | A new subscriber could duplicate ownership or misrepresent replay if not serialized and bounded. |
| user-entered Run ID → fixed Runs endpoints | Untrusted recovery input must not select hosts, paths, or query parameters. |
| recreated panel → prior run | No trusted local state survives recreation; only fresh credentials plus Gateway status establish current truth. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-01-01 | Information disclosure | recovery credentials and state | high | mitigate | Keep bearer in controller/relay stdin memory, clear it on release, and prohibit storage/evidence/rendering. |
| T-03-01-02 | Tampering / Repudiation | event reattach semantics | high | mitigate | Reconcile status after every interruption and permanently disclose that event delivery is not lossless or exactly once. |
| T-03-01-03 | Denial of service | observer retry loop | high | mitigate | Allow two fixed reattach attempts only, serialize after prior cleanup, and invalidate on generation change/release. |
| T-03-01-04 | Elevation of privilege | manual recovery endpoint | medium | mitigate | Validate the existing safe Run ID grammar and construct only fixed status/events/control paths already capability-gated. |
| T-03-01-05 | Spoofing | stale approval detail | high | mitigate | Clear approval state on interruption/recreation and render it only from a new allowlisted event. |
| T-03-SC | Tampering | npm supply chain | high | mitigate | Add no package or install task; retain the current lockfile and built-in APIs. |
</threat_model>
